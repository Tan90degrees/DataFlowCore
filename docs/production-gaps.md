# 内部工业组件的验收与边界（0.7.0）

本项目承担宿主产品内部的文件任务执行，不承担人员身份、权限、租户、管理审计或
算子市场。依赖在业务镜像里统一维护，算子不动态安装。一个文件的完整 Attempt
绑定一个执行器和常驻槽位，故障从头重试，没有断点续跑。

| 目标 | 当前机制 | 验收依据 |
| --- | --- | --- |
| 资源利用 | 算子级共享预算、CPU/IO 独立固定池、公平回填、老请求保护 | 同执行器跨文件预算不超限，IO 绕行与大请求等待测试 |
| 高吞吐 | 常驻进程/线程池/缓存；完成事件驱动复用；批量续租与领取 | 文件入库完整流程、固定 PID 复用、默认/积极通信间隔对比 |
| 低底噪 | 空闲槽位阻塞等派发；只唤醒获准的资源等待者；健康原子快照不 fsync | 空闲 HTTP 数、日志字节和可用时的进程 CPU 采样 |
| 控制面效率 | 有界 PG 连接池；配置只在建连时设置；不载入未变化的大进度；空闲回收扫描只读 | PG 连接复用、损坏连接替换、快照隔离、连接池指标 |
| 易用性 | 只配置节点资源；前端仅填写 API 地址；上传、编排、观测、停止 | 真实浏览器全部业务与运维用例 |
| 可靠性 | 持久事务、幂等领取/完成、有效期、防旧结果覆盖、进程组回收 | 丢失批量响应、单项租约失效、阻塞通信下的独立看门狗 |
| 故障恢复 | 单活管控所有权检查，Pod 重建，持久文件与元数据，整文件重试 | 三节点 K8S 杀 Pod、管控重启、恢复后继续提交 |
| 可定位性 | 会话/槽位 generation/Attempt 关联；等待原因、进度、尾日志、历史详情 | 排队原因、资源快照、PID 复用识别、固定标签指标 |
| 长期运行 | 背压、维护静止状态、失败目录保守清理、原生备份恢复、版本锁定 | 并发接入、维护/GC、pg_dump/pg_restore 后历史哈希与新文件 |

不为新数据库创建 audit 表，不写管理审计；升级保留旧表中的历史数据。任务业务事件
继续保留，它们用于执行诊断和恢复。旧单项 worker API 可续租已有执行；新执行器
使用 pulse。升级时先停旧管控，复用原 PG/schema 和数据卷，更新前后端及 Helm。
任务绑定的 pool/runtime_version 不会自动升级；业务镜像版本变化时保留匹配的执行器
处理旧队列，再排空旧环境。

使用 [生产运维](production-operations.md) 和 [性能报告](internal-performance.md) 定位
与调优。性能脚本保存版本、源摘要、配置、每轮测量和业务校验；测试模型不代表真实
OCR、LLM、GPU/NPU 或生产数据库/存储的吞吐。

仍有明确的容量边界：

- 管控是单活服务，K8S 重建后可恢复；尚无透明主备切换或无停机升级。
  PostgreSQL 和 RWX 的可用性由平台提供，恢复时间还包含平台重建时间。
- 文件槽位是执行中的文件上限。长 IO 文件占满槽位时 CPU 仍可能空闲，按实测调整
  slots；它不改变任务资源配置。多个文件共享同一进程/重模型的方案会改变取消与
  故障影响范围，属于单独的架构扩展。
- 调度优化的是声明资源，实际 RSS 还包含缓存、线程栈和中间数据。给 Pod 留余量，
  不能把最大单算子内存直接当作实际峰值，也不宣称未知执行时长下的全局最优。
- 成功文件、输入与元数据当前保留，需要宿主产品的生命周期/归档策略。真实业务的
  持续负载、长尾模型调用与目标硬件验收，仍需在产品环境完成。
